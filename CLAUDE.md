# CLAUDE.md: working rules for this repo

You are helping build `esci-hybrid-search`. Read this file fully before any change.

## Source of truth

1. `docs/EVAL_PROTOCOL.md` is **frozen**. Never change it to fit a result. If a change is
   genuinely needed, write an ADR in `docs/adr/` that explains why, *before* rerunning anything,
   and record the change in the protocol's "Amendments" section with the date.
2. `docs/specs/*.md` define every module's public interface, behavior, and tests.
   Code must match the spec. If the spec is wrong or incomplete, **update the spec first**
   (in the same PR) and say so in the PR description.
3. `docs/FILE_MANIFEST.md` lists every file that should exist. Do not create files that are
   not in the manifest without adding them to it.

## Workflow for every task

1. Read the relevant spec section(s). Quote the section ID (e.g. `SPEC-03.4`) in your plan.
2. Write or extend tests **from the spec's "Tests" list first**. Run them and confirm they fail.
3. Implement until they pass. Keep functions small and typed.
4. Run `make check` (ruff + mypy + unit tests). It must be green before you say "done".
5. Write a short **Verification** note: what you ran, what output proved it works, and what
   you did *not* verify.
6. If you (the AI) produced code that turned out wrong and a test or a review caught it,
   add an entry to `docs/AI_USAGE.md`. This log is a deliverable, not a formality.

## Hard rules

- **Never touch the test split** (`split == "test"`) outside `make final-eval`.
  Tuning, debugging, and plots use the `dev` split only (see `SPEC-01.3`).
- **Never invent numbers.** README/RESULTS numbers are generated by `scripts/make_results_table.py`
  from `results/runs/*/metrics.json`. Do not type metric values by hand anywhere.
- **No secrets in the repo.** AWS credentials come from the environment or OIDC.
  DB passwords come from Secrets Manager (cloud) or `.env` (local, git-ignored).
- **Cost guard.** Do not run `cdk deploy`, Bedrock calls, or anything billable unless the
  user explicitly asks in this session. Bedrock experiments must respect `bedrock.max_queries`.
- **Determinism.** Every random choice takes a seed from config. Default seed: 42.
- Prefer the standard library and the dependencies already in `pyproject.toml`.
  Adding a dependency requires a one-line justification in the PR.

## Commands

| Command | What it does |
|---|---|
| `make check` | ruff, mypy (strict on `src/`), unit tests |
| `make test` | unit + integration (needs `make up-local`) |
| `make up-local` / `make down-local` | start/stop local Postgres+pgvector and DynamoDB Local |
| `make data` | download + verify ESCI, build splits, write data card |
| `make index` | BM25 index, embeddings, Postgres load |
| `make eval EXP=<name>` | run one experiment from `configs/experiments/<name>.yaml` on dev |
| `make final-eval` | test-split run of all frozen configs (guarded, see SPEC-04.6) |
| `make results` | regenerate `results/RESULTS.md` and README table |
| `make serve` | run the FastAPI service locally |
| `make loadtest SCENARIO=<name>` | k6 against `$TARGET_URL` |

## Style

- Python 3.12, type hints everywhere, `from __future__ import annotations`.
- Package: `src/esci_search/`. Imports are absolute (`from esci_search.eval import metrics`).
- Logging: `esci_search.logs.get_logger(__name__)`, JSON in the service, plain text in CLIs.
- Docs and code comments in English.
