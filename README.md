# esci-hybrid-search

A hybrid (lexical + dense + rerank) product search service, evaluated on Amazon's
human-labeled **Shopping Queries Dataset (ESCI)** and deployed on AWS
(ECS Fargate, RDS PostgreSQL + pgvector, DynamoDB, Bedrock).

> **Status:** spec phase. No code yet. Every file that will exist is specified in
> [`docs/FILE_MANIFEST.md`](docs/FILE_MANIFEST.md) and implemented against the specs in
> [`docs/specs/`](docs/specs/).

## Why this project

The question: how much does each layer of a modern search stack actually buy you, in
**relevance**, **latency**, and **cost**, on real e-commerce queries with real human labels?

The relevance numbers come from Amazon's ESCI annotations, not from us. Latency comes
from k6 load tests, and cost from AWS billing data. All three are reproducible with one
command per phase.

## Quickstart (target, once implemented)

```bash
uv sync                      # install deps (Python 3.12)
make up-local                # Postgres+pgvector and DynamoDB Local via docker compose
make data                    # download ESCI, verify checksums, write data card
make index                   # build BM25 index, embeddings, load Postgres
make eval EXP=p4_hybrid      # run one experiment on the dev split
make test                    # unit + integration tests
make serve                   # run the API locally on :8000
```
